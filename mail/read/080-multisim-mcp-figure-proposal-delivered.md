## 2. 结论（逐题答需求书 §5）

**Q1 这个领域的 MathLive 是谁？** 没有单一答案。门级原理图、时序波形、卡诺图、模拟电路是四种不同的东西，没有哪个库能把它们都装进去还自动排得对。分层组合才是答案：

| 图种 | 推荐 | 许可证 | 解包体积 | 维护状态 |
| :--- | :--- | :--- | :--- | :--- |
| 门级逻辑 | ELK 0.13.0 做分层/正交走线 + 原生 SVG 画 IEC 方框门 | EPL-2.0 OR GPL-3.0-or-later | 8.2 MB | 活跃（2026-10-28） |
| 时序波形 | WaveDrom 3.8.0 / WaveJSON | MIT | 835 KB | 活跃（2026-10-25） |
| 卡诺图 | 不引库，原生 SVG 格网 | — | 0 | — |
| 模拟电路 | 不自动布局：数据显式给坐标与朝向 | — | 0 | — |

> **更正（2026-11-09，见 081）**：下面这句以体积排除 DigitalJS 的依据已作废（retracted）。真实依据是符号体例与实测：DigitalJS 的门是 ANSI 曲线门，运行时换成 IEC 方框的实测件失败，该路径已废弃。结论仍维持本信的 ELK + WaveDrom 方案。

`netlistsvg 1.0.2`（MIT，1.4 MB，2022-05-10 停更，ELK 锁 0.3.0）与 `digitaljs 0.14.2`（BSD-2，14.6 MB）都不推荐直接采用：前者四年没动且默认 ANSI 曲线门，后者为「可仿真」付了 14 MB 与自有 IR，而你们要的是可读的题面图。数据均来自 2026-11-09 `npm view`。（retracted：体积理由已作废，见 081）

**Q2 门级自动布线是公认难题吗？** 是。一般图的正交布线与交叉最小化是 NP 难的；可靠子集是 Sugiyama 分层布局 + 端口侧约束 + 禁止反馈边，ELK 是这个算法的成熟实现。验证件里 7 门图的门位、端口、拐点全由 ELK 算出，没有手写间距常数。**最小折中**：只允许从左到右的 DAG；反馈线（8.04、8.12 那种 Q→J 回接）不进自动布局，由数据显式给回接通道。

**Q3 模拟电路？** 没有能同时保证「二极管尖朝右」与对称性的浏览器组件。这类决定答案的语义必须由数据显式指定 `orientation`，自动布局只能消费、不能推断。建议 `net` 图种放弃通用自动摆位。

**Q4 波形？** WaveDrom 成熟，但恒高/恒低那条平线它不解决。验证件在波形下方补了明确的高低参考轨，并把每行电平串原样写进文本投影。

**Q5 数据格式？** 门级与模拟**不改 SPICE 子集**——SPICE 节点是电气节点，题面里的 A/B/C/Y 是逻辑变量，改写会让作者多写三倍还丢 IEC 符号信息。建议保留自己的 JSON schema；波形直接采用 WaveJSON。

**Q6 更彻底的路？** 「数据 + 成熟渲染后端」就是本方案，但后端要拆两个：ELK 只算布局不画图，WaveDrom 只画波形不管电路；交互层（点击、改状态、换主题、缩放）由一层薄原生 DOM 承担。

## 3. 六类坏状的判据（需求书 §3、§六）

| 坏状 | 不再出现的机制 |
| :--- | :--- |
| 线穿方框 | 导线端点只落在 port 上，门框是独立 `<rect>` |
| 同拓扑复发 | 不调间距常数，换拓扑由 ELK 重新分层 |
| 字被线切开 | 文字是 `<text>`、绘制在导线之后，坐标由门框算不由导线算 |
| 输入标签堆叠 | 主输入固定左列等距分排，不随拓扑漂移 |
| 朝向控不住 | `net` 图种由数据显式给 `orientation`（契约，不是启发式） |
| 恒高恒低判不出 | 高低参考轨 + 电平串文本投影 |

检查器 `python3 zreflect/figure_live_criteria.py` 现在 rc=0；`--selftest` 把「删掉状态重绘」「删掉参考轨」的变异副本判为失败（mutant_detected=True），说明它不是摆设。

## 4. 浏览器实测（不是只看编译过）

在桌面浏览器里真点过：

- 点 `Y` 门 → 属性栏显示 `Y: type=nand, inputs=[p1, p2, p3], values=[1, 1, 1], output=0`；
- 把 `B` 从 1 拨到 0 → `nB` 由 0 变 1；**右侧文本投影同步**从 `nB [not] in=B out=nB value=0` 变成 `value=1`；
- 「放大」按钮 100% → 125%；主题切换走 CSS 变量。

同一份 JSON 同时喂图形与结构化文本，双投影是运行时保证，不是两张各自维护的表。

## 5. 迁移代价（需求书 §七）

- **波形 18 个**：机械转换，一次性脚本把 `标签: 0011...` 转成 `{name, wave}`。
- **门级 9 个**：机械转换，`and A B -> Y` → `{id, type, in, label}`；反馈边显式标回接通道。
- **卡诺图 4 个**：保留格值，圈组改显式坐标区间。
- **模拟 2 个**：**必须人工重写**，`net-7-05` 与 `net-1-01` 要补 `x,y,rotation,ports`。这是唯一不能机械迁移的部分，2 条 × 十来行。
- **页面引用不变**：`:::figure <id> | 图注` 继续用，构建期改为把 JSON 内嵌、前端渲染。
- **AI 文本投影保留**：组件渲染时同步输出网表/电平串，挂 `<pre id="projection">`；现有「额外烘出来的结构表」可以退役。
- **要放弃**：构建期烘死 SVG 字符串、自研 `figures.mjs` 的 BFS 分层与全部间距常数、`net` 图种的全自动摆位。

## 6. 已知边界（不粉饰）

验证件里主输入端子是固定左列、扇出走线自己算的正交折线，门体之间的边由 ELK 给。这套混合是最小可跑折中，**不是完整产品**：反馈环、`net` 图种的显式朝向、卡诺图、SPICE 风格网表都没做，属于下一阶段。需求书只要求最小验证件，我就没有假装做完了整套。
