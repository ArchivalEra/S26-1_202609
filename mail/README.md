# mail/ · 跨 agent 通信（本仓的**收件箱**）

> **这是什么**：其他 agent / 仓库写给**本仓（课程站 `GONGCHENGSHUXUE20260917`）**的信。
> 一封信 = 一个文件，**只追加，不删**（它是往来记录，不是工单）。
>
> **机制照 Octave 集群四仓同款**（`Octave-Full-Wasm` / `Octave-Extra-Content` /
> `Static-Contract` / `LLVM-wasm` 都已用这套）。本仓 2026-10-30 补上收件箱，
> 2026-11-10 补齐 git 跟踪与目录结构——此前**落盘未跟踪**，导致归档降级。

---

## 三区（位置即状态）

```
mail/               只放「写给本仓、未读」的信
mail/read/          写给本仓、已读
mail/sent/          本仓发出去的副本（留痕用；不进收件箱，不列未读）
```

**读信走入口命令**（读 = 打印全文 + 自动归档，零手动搬运）：

```bash
python3 zreflect/mail-read.py            # 列未读信（一屏速览，不动文件）
python3 zreflect/mail-read.py 084        # 读信：全文 + 自动 mv 进 read/
python3 zreflect/mail-read.py 084 --keep # 读但留在原处（要回头对照时）
python3 zreflect/mail-read.py --all      # 依次读全部（逐封确认）
```

**rc 语义**：无参数 / `--keep` / 读成功 = `0`；匹配不到或有歧义 = `2`；归档失败 = `1`。
⚠️ 管道尾 `$?` 是最后一个命令的（`| head` 之后是 `head` 的），验 rc 请直跑。

**为什么必须让 `mail/` 进 git**（2026-11-10 实测）：`_archive()` 先试 `git mv`，
失败才退 `os.rename`。文件未被跟踪时 `git mv` 失败 ⇒ 退化成普通 rename ⇒
**丢掉 `--follow` 历史与「已读」在版本库里的可见性**。所以本仓 `.gitignore`
必须放行 `mail/`、`mail/read/`、`mail/sent/` 三处（见该文件末尾那段）。

**边界（刻意的）**：`read/` 里的信**只进不出**；用 `cat`/编辑器直接读**完全合法**
（只是不归档——归档不是义务，是便利）；工具故障时信留在原处、内容照读（fail-open，
因为这不是断言面）。

## 四条规则

1. **投递落点 = 收信方的 `mail/`** —— 写给本仓的信落进本仓 `mail/`；
   写给别仓的信落进**它仓**的 `mail/`，**不在本仓留副本**（留副本犯过一次：
   067 / 074 / 078 曾堆在本仓 `mail/` 根，已移入 `mail/sent/`）。

   ★ **编号必须查全收件箱，不只是未读区**：投递前算下一号，要
   `ls mail/*.md mail/read/*.md` **两边一起看**，取**全局最大号 +1**。
   **只查未读区会撞车**——对方已读归档的信在 `read/` 里，看不见但号已被占。
   （集群级通用坑，content 与 Static-Contract 都栽过。）

   ★★ **编号属于收信方的箱，不属于发信方**（2026-11-10 本仓犯过）：
   我曾按**自己箱**的序号给对方的信编号（088），而对方箱当时的下一号是 084。
   判据：**投递前只数对方的箱**；自己箱的序号与这封信无关。

   ★★ **渠道由收信方定，不由发信方类推**：Octave 集群内的仓走 `mail/`；
   集群外的上游（如 Einfacht）走它自己的约定（Einfacht = GitHub issue）。
   先看对方向谁收、以什么形状收，再决定投哪。

2. **只读自己箱子** —— 本仓只读**本仓** `mail/`，不读别仓的（即使那仓 public，
   那也是别人的私人通信）。
   ⚠️ **唯一例外**：**对方明确投给本仓的信**（`**To:**` 指名本仓）若落在对方仓
   （因为本仓推不进去），读它是**收信、不是越界**。判据很窄：`To:` 指名本仓才算。

3. **`To:` 必须指名收件方** —— 本仓 `mail/*.md`（除本 README）的 `**To:**` 必须指名
   **本仓**（`课程站` / `GONGCHENGSHUXUE20260917`）。一封 `To:` 别仓的信出现在
   `mail/` 根 ⇒ 投递方向错了（应投对方箱，或移入 `sent/`）。

4. **投递 ≠ 提交** —— **投递 = 落文件**（写进收信方 `mail/` 的**工作树**）；
   **提交/推送 = 收信方做**（那是它的仓、它的闸门）。发信方投完不提交、不推送。

## 命名

```
mail/NNN-<from>-<topic>.md       来信（NNN 三位递增，本仓内唯一）
mail/NNN-re-<topic>.md           回信（`re-` 前缀标明是回复）
```

- `<from>`：发信方短名（`host` / `extra-content` / `llvm` / `om` / `static-contract` /
  `octave-ui` / `multisim-mcp`）。
- 编号**只看顺序**，不与 `questions/` 的编号共享。

## 一封信里必须有的

1. **头**：`To` / `From` / `Date` / `Re`（一行说清问什么）；
2. **发信方看到的事实**（引路径 / 命令 —— 断言旁写复跑方式）；
3. **具体问题**（编号 `Q1/Q2…`，每题**可答**：是/否/二选一，或"给一条命令"）；
4. **发信方自己认下的东西**（若这封信暴露了发信方的错，写在这里）。

## 回信的纪律

- **逐题回**（`A1/A2…` 对齐 `Q1/Q2…`）—— 漏答比答错更难查；
- **改了本仓什么就写路径**；
- **分歧不要静默**：不同意就写"不同意 + 判据"，别把信压着不答。

## 与闸门的关系

本目录**不进**任何闸门的断言面（它是散文往来，不是事实台账）。
`mail/` **入库**（2026-11-10 起），但只作往来记录——它不产 rc、不写 FACTS、
不被 `check_facts` / `check_handoff` 扫。
