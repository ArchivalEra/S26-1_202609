# 三签：读了依赖，做不做得出来

**双签管「答案对不对」，三签管「照着依赖能不能做出来、过程讲不讲得通」。** 两者问的不是一件事：

| 关卡 | 问什么 | 谁来做 | 信息隔离 | 能不能改仓库 |
| :--- | :--- | :--- | :--- | :--- |
| **双签** | 答案**数值/结论对不对** | 独立子代理，**只拿题面** | 不给解答 | **只报差异，不改**（改了就不独立了） |
| **三签** | 读了**依赖**会不会做 + 过程合不合理 | 另一个独立子代理，**只拿题面 + 依赖指向的内容** | **不给解答** | **可直接改**依赖锚点与作业页步骤（见「权力与红线」） |

**顺序**：题面入库 → **双签**（答案先对）→ **三签**（依赖再够）。**答案没验过就别跑三签**——答案错了，讨论依赖充分性没意义。

## 三签的输入（信息隔离是命根子）

三签子代理**拿到**：
1. **题面**（从作业页抽出，与双签同一份）；
2. **依赖表里每个链接指向的内容**（把锚点目标页面的对应段落整段抓给它）。

三签子代理**不拿**：作业页的「提示/完整解答/复盘」——给了它就退化成「看了解答当然会做」。

> 依赖表在作业页的「## 2. 依赖」节（`| 题组 | 做之前先过掉（点击直达） | 到那里你该已经会了 | … |`）。
> 没有依赖表 → 三签第一件事就是报「本页没有依赖表」，并补一个（这正是三签要抓的）。

## 两步走（先盲做，再评解答）

**第一步 · 盲做（判依赖是否自足）**：只凭题面 + 依赖内容，试着把题做出来。报告：
- 做出来了吗？卡在哪一步？
- 卡住是因为**依赖里没有**那条定理/法则/定义，还是**依赖里有、但没讲到点子上**（锚点指偏了）？
- 有没有需要**依赖之外的额外知识**才能继续？

**第二步 · 评解答（判过程是否合理）**：这时才把作业页的解答给三签，逐条核对：
- 解答用到的**每一条定理/法则**，在依赖指向的内容里**查得到**吗？（**定理闭合**——最常出问题的一条）
- 每一步有没有**依据**？有没有跳步、有没有「显然/容易看出/巧妙」这类反人类表述？
- 读者**只拿题面 + 依赖**，照这个解答走一遍，能不能得到同样的结果？

## 判据（机械可查，逐条对）

| 判据 | 怎么查 | 不过怎么办 |
| :--- | :--- | :--- |
| **依赖自足** | 只拿题面 + 依赖，能否独立复现解题思路 | 依赖不足 → **补依赖**（加锚点或补依赖指向页面的内容） |
| **定理闭合** | 解答里每条定理 vs 依赖覆盖范围，逐条比 | 缺哪条 → 把那条**补进依赖指向的页面**，或依赖表加一行指向它 |
| **锚点有效** | 点开依赖表每个链接，看内容是否真覆盖「到那里你该已经会了」那一列 | 指偏/失效 → **改锚点** |
| **过程无跳步** | **逐步**核：每一步是否写明「这一步在做什么、依据哪条法则」；有无「显然/容易看出/巧妙/一眼看出」 | 跳步 → **补步骤/补依据**（见下「跳步的四种真身」） |

> **「定理闭合」是最关键的一条**，也最容易漏：解答用了消去法 $X+\overline{X}Y=X+Y$，
> 而依赖表只指向「基本定律」，那一节里**没讲消去法**——读者读了依赖照样做不出来。
> 判据：**把解答里出现的每个定理名，到依赖指向的内容里逐个搜一遍**；搜不到就是闭合缺口。

### ⭐ 跳步的四种真身（三签的核心职责，**逐条必查**）

「跳步」的**成因**只有一种（中间量未演算），落到页面上是三种症状——扫描时分两轮：
先按**机械判据**全文搜症状（③④ 一搜即知），再逐题人工核成因（①② 要读步骤）。

| # | 真身 | 症状/成因 | 扫法 | 改法 |
| :-: | :--- | :-- | :-- | :-- |
| 1 | **依据缺失** | 结论句附近没有法则名 | 逐句读 | 补依据，每步标法则名 |
| 2 | **中间量未演算** | 「→」两侧缺可复算的中间式（成因本体） | 逐题读 | 把中间步显式写出 |
| 3 | **草稿残留** | 「等等——」「更规范地写」「其实应该」「换一种写法」 | **全文搜**，应为 0 | 删错误版，只留最终写法 |
| 4 | **编号错乱** | 两个「第二步」/跳号/标题与正文路数不符 | 逐题对 | 重排编号，标题对齐实际做法 |

例（2 类）：卡诺图圈出后直接写 $Y=B$，没写「这一圈里 $B$ 不变、其余变量相异被消」。
例（3 类）：`Y=(A+B+C)(A+B+C)` 后跟「等等——三项是 $A(\cdots)+B(\cdots)$…」——
读者会以为有两个答案。

## 权力与红线

**可直接改**（不必等主会话）：依赖表（补行/改描述）、依赖锚点（改指向）、作业页的步骤表述
（补跳步、补依据、把「巧妙看出」改写成机械做法）。**不许碰答案数值**——怀疑答案有问题，
退回双签重算，不自己改数；题面只按来源核对，不按「好不好懂」改。

**改完必须**：① 重跑钩子与构建（`update-readme.py --worktree` + `node build.mjs`）；
② 若改动涉及答案相关文字，**重跑双签**（三签的改动可能引入新错）。

## 执行清单

1. **前置**：确认这一页**双签已过**（完成边界里有双签行）。没有 → 先跑双签。
2. **抽料**：从作业页抽出**题面**，以及**依赖表每个锚点指向的内容**（整段）。
3. **盲做**：派独立子代理，只给「题面 + 依赖内容」，要求它试做并报告卡点（禁止读作业页解答）。
4. **评解答**：把作业页解答给同一个（或新的）子代理，逐条核对「定理闭合 / 无跳步 / 可复现」。
5. **落笔**：
   - 依赖自足且过程合理 → 在完成边界写一行
     `三签：<日期>，独立子代理只读依赖试做，可独立完成；解答过程合理（定理闭合、无跳步）`；
   - 有缺口 → **直接改**依赖锚点/步骤（在权力范围内），改完重跑钩子+构建，必要时重跑双签，
     再写三签行（写明改了什么）。
6. **交主会话**：三签改动过的文件，主会话按正常流程提交推送。

## 别把这些当三签

- 只把解答念一遍打勾（没做题，验不出「依赖够不够」）；
- 拿「我看懂了」当结论（看懂的是**解答**，不是**依赖**——三签的判据是「只读依赖能不能做」）；
- 三签顺手改答案数值（越界，且答案正确性要独立重算才算数）。
