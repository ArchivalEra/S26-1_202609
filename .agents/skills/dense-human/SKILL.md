# 密话：短、准、密

写给人速查的文本。**两个失败模式，都算没写完**：

- **咕噜话**：句子多、信息少（包装语、重复、自证、空转场）。
- **压丢精度**：为了短而丢数字、条件、否定、范围、谁说的。

## 四条判据（逐句可机械执行）

1. **删句测试**：删掉这句，读者少知道什么？说不出具体东西 → 删。
2. **复述测试**：读完能复述出一个事实、判据或动作？不能 → 重写或删。
3. **重复测试**：同一事实全页只出现一次；第二处要么是锚点、要么删。
4. **保真测试**：压缩前抄下七项——**数字 · 专名 · 条件 · 否定 · 范围 · 时间 · 谁说的**——
   压缩后逐项核，少一项 → 放回。（「谁说的」是本仓常混项：教师口述 / 教材原文 / 视频旁白 / 整理推断，四种来源不能互串。）

过了判据，剩下的材料进入重打包——压缩的收益大半来自这里，不来自删字。

## 高密度靠重打包，不靠删字

- **结论先行**：先给判据/答案，再给理由；别从背景爬到结论。
- **并列排表**：三条以上并行信息 → 表格或列表；散文只留给有因果的叙述。
- **案例压一句**：谁 + 做了什么 + 关键数字。
- **过程压判据**：多步推导只留「入口判据 + 关键分叉」，中间步靠锚点回原文。
- **术语直用**：读者必须会的行话直接用 + 锚点；不能用而不解释 → 一句话定义。

## 动笔前

先看目标页**已有的骨架**（各页自己的框架优先）：只在句段层工作——删包装、并重复、排表格、提前结论；
**不搬骨架、不换体例**。

## 边界

- 数学解析/作业解答 → `human-first-solution`（机械做法），本 skill 只管表达。
- 单篇审稿、去 AI 味、改别人的稿 → `shuorenhua`（措辞保真的细则在那边，不重复）。
