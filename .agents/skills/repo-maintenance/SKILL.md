# 学期课程仓库维护

`课程/<课名>/` 五类：作业、教材解析、课堂笔记、原始资料、音频（没有该类的课程在
`.githooks/hook_lib.py` 的 `COURSE_SKIPPED_KINDS` 声明豁免）。操作规程 `维护细则.md`、原则 `维护条例.md`，
冲突以条例为准。**判据：钩子全绿、网页能读。**

**先选一条线**，照做完；每条线末尾的判据就是完成条件。

## 笔记线：课堂转写 → 课堂笔记

1. `python3 .githooks/extract-transcript.py <源.doc>` → 纯文本 + 元信息（时间戳范围、说话人、手机号命中），**通读一遍再落笔**。
2. 写 `课程/<课>/课堂笔记/YYYY-MM-DD-名称.md`，骨架照 `模板/课堂笔记.md`（2026-09-24 起改成这个形状）：
   **这节课在干什么 → 行政与考核 → 题号条目（解析 + 这一题在讲什么）→ 没编号但讲了的知识点 →
   本篇没讲的 → 转写与术语 → 待办**。正文只写两样：**题怎么做**、**老师为什么这么讲**；
   溯源/时间轴/SHA-256/隐私说明不抄进来（那些在 `原始资料/index.md`）。
   题号用老师自己的编号；有题号但找不到教材、或条件不全 → 只写站得住的推导链条，缺的挂末尾**待办**，不补造数字。
   题号条目里的解析要过两道闸（反人类解析 + 盲测）；转写把术语读错的，就地标一句 + 收进「转写与术语」。
3. 三处登记，**最小 diff**：`课堂笔记/index.md` 加一行、`原始资料/index.md` 加一行并更新共同说明、`课程/<课>/index.md` 改「资料入口」那一格。
4. 白名单加两行（`.md` 与 `.doc`）、`站点/build.mjs` 的 `TARGET_FILES` 与 `NAV` 各加一条。
5. 收尾一条（下下节）→ `git push`。

判据：`update-readme.py --worktree` 绿、构建页数 +1、笔记末尾有「待办」且与正文缺口一致。

## 作业线：学习通任务 / 习题 → 作业页

1. 题面：截图 → 按 [读图提示词.md](./读图提示词.md) 派子代理**逐字抄题干与选项**（只抄题面，不让它作答）；文本 → 直接抄。
2. **过两道闸**（下节），拿到双签行。
3. 写 `课程/<课>/作业/YYYY-MM-DD-名称.md`，骨架照 `课程/工程数学/作业/2026-09-17-作业1.md`：
   怎么用 → 依赖表 → 逐题「提示／完整解答／复盘」折叠（默认收起）→ 小结 → 完成边界（含双签行）。
4. 登记同笔记线第 3、4 步（`作业/index.md`、`原始资料/index.md`、课程 index、白名单、TARGET_FILES/NAV）。

判据：双签 N/N 全一致、钩子全绿。

## 课程线：新增一门课

从 `模板/` 复制五类 `index.md` 建 `课程/<课名>/`，`课程/index.md` 登记，白名单五条，
`TARGET_FILES` 与 `NAV` 各加一节。判据：钩子全绿、站点侧栏出现新课（**NAV 没有钩子校验，人眼核一眼**）。

## 两道闸（解析／作业／攻略必须过；课堂笔记不受限）

- **反人类解析**：「试探／凑／巧妙看出／注意到」= 没写完 → 换成机械做法（找线性关系 = 挑 0 最多的行消元；
  定基准行/列 = 由矩阵里现成的 ±1 决定）。判据：**读者只拿题面、照步骤能做出同样结果**。细则见 `human-first-solution`。
- **盲测**：子代理只拿题面、禁读仓库，独立算出答案 → 与整理者的答案逐题对照 → 全一致才在「完成边界」写一行双签；
  不一致就只报差异、一个答案都不改。细则见 `double-sign`。
- 教材解析另外三件事：**先抄后析**（原书抄录紧跟解析）、**一节一个文件**、
  **`fractions.Fraction` 精确验算**。样板见 `课程/工程数学/教材解析/第一部分-线性代数/`。
  学生手写答案是草稿，不是标准答案。

## 收尾一条（复制即用，一次跑完六项）

```bash
python3 .githooks/update-readme.py --worktree && python3 .githooks/test-update-readme.py \
  && python3 .githooks/check-markdown.py && (cd 站点 && node build.mjs) \
  && git fsck --no-progress && git diff --check
```

改过 `课程/` 或 `站点/` → 同轮更新 `.zcode/handoff.md`（pre-commit 强制）。
提交被拦就按提示修命名、索引或两处 AUTO 区块（那两个区块由钩子从暂存区重算，交给它写）。

## 卡住时

- **白名单**：`.gitignore` 是 `*` → `!*/` → 逐文件 `!/完整相对路径`，无通配符；先加白名单再 `git add`（漏了本地能过、CI 必挂）。
- **跨课程链接**：在 `课程/A/课堂笔记/` 里写 `../../B/index.md`。
- `git fsck` 报对象损坏：核对工作区哈希 → 删 `.git/objects/xx/…` → 重新 `git add` → 重跑。

## 性能纪律（入库预算：2–3 分钟、**约 6 次工具调用**）

一次入库就六步：①提取转写 → ②通读 → ③写正文 → ④登记（4 个文件**一批改完**）→ ⑤收尾一条 → ⑥推送。
调用数明显超出，就是哪里在重来一遍。

- **同一会话已挂过本 skill → 不重复挂**（正文不会变，每次重挂约 2k token 纯属浪费）；每个新会话的第一条内容任务照常先挂。
- **转写用第 1 步的脚本提取**，随手重写 python 解析是浪费。
- **索引最小 diff**：只加行、只改 `last_updated`，不整篇重写，也不先通读（新写的内容本就在上下文里）。
- **handoff 最小更新**：§1 该课那一行 + §6 该课小节追加 2–4 行 + §9 加一行。
- **推送即结束，禁止等 CI**（2026-09-24 用户定案）：本地构建与 CI 等效（同一个 `node build.mjs`、同一套钩子），
  所以 `git push` 就是终点——不 `sleep`、不轮询、不为「看 CI 绿不绿」多花一分钟；线上页面只在改动 `站点/`
  或用户要看时抓。只有部署步骤本身报错（如密钥被拒）时才偶尔看一眼运行状态。
- 读图规程（含照抄用的提示词模板、照片登记）在 [读图提示词.md](./读图提示词.md)，有图才打开。
