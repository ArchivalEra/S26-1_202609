# 学期课程仓库维护

本 skill 把仓库的维护流程固化下来。仓库以**中文课程名**为主分类，每门课有五个固定类别：作业、教材解析、课堂笔记、原始资料、音频。课程数量可以任意增加，流程不变。

**动手前先读这两份**：`维护细则.md`（操作规程与自动状态区块）和 `维护条例.md`（原则）。本 skill 只讲怎么执行，冲突时以那两份为准。

## 铁律：图片必须交给子代理读

教材照片的阅读**一律派子代理**（Agent 工具，`general-purpose`）。原因很实际：**主对话每对话最多 60 张图片**，超限后主代理读不了图，整批任务会卡死；子代理有独立的图片预算，不受这个上限影响。

具体做法：

1. 主代理先用 ImageMagick 生成**临时阅读副本**（方向校正 + 缩放），放在 `/tmp`，不要动原件：
   ```bash
   magick "源图.heic" -auto-orient -resize 2000x2000 -quality 88 "/tmp/batch/名字.jpg"
   ```
2. 用 Agent 工具分批派活，**一个子代理读 4–8 张**。提示词必须写清：这是哪本书的哪一章哪一节、期望的页码区间、要逐字核对的记号（箭头上的行变换标注、上下标、正负号），并要求区分「数值确定」与「标注看不清」。
3. 子代理返回文字结论，主代理只汇总，不重复读图。
4. 主代理只在需要目视确认**一两个关键点**时才自己读图，并算进自己的 60 张预算；预计本章照片超过 20 张时，从一开始就全部走子代理。

**每张图只读一次；看不清就上报重拍。** 这是硬规则，违反等于浪费用户的钱：

- **每张图只允许 Read 一次**。禁止重复打开、禁止换副本再试、禁止"再确认一下"。
- **只问具体问题，不许抄整页**。提示词里列出要读的那几行字（某个下标、某个标注），明确写"不要转录整页正文"。读整页会烧掉十几倍 token。
- **一次派完、一张一读**：需要核对 N 张图就一张图一个问题，一次派完，不循环重试。
- **读不清就直接报给用户重拍**，不要自己想办法（不许裁剪、放大、增强、换格式、找替代路径）。上报格式：`文件名 + 原书页码 + 看不清的具体位置 + 原因`。
- 正常情况下单张图约 1 万 token 内完成；若某次读图超过这个量级，说明提示词写错了（多半是让它抄整页）。

**禁止用 OCR 代替读图。** 实测中文 OCR 会把矩阵里的 `1`、负号、下标全部读错，把 `2 1 3` 读成 `2 3`。OCR 只允许用来快速定位页码，不能作为转录依据；子代理必须真的看图。

**子代理只许"看图"，不许"想办法把图变成文字"。** 实测有子代理收到"读照片"的指令后，自己建虚拟环境、装识别工具、把图旋转缩放截图做探针——这是被明令禁止的路线，浪费一整轮，且一个字都不能用。提示词里必须写死三条：

1. **只允许 Read 工具看图**；禁止使用或安装任何 OCR／文字识别工具或模型（tesseract、pytesseract、easyocr、paddleocr、Umi-OCR、系统 OCR API 等），禁止 `pip`／`uv`／`apt` 装任何东西。
2. **禁止加工图片**（旋转、裁剪、缩放、增强、拼接）。需要方向校正或缩放时，由主代理先用 ImageMagick 生成 `/tmp` 阅读副本，子代理只读副本原件。读不到、看不清就**立即停止并如实报告**，不要另寻替代方案。
3. **报告开头先声明**：本次用 Read 实际打开的文件清单、未能打开的文件；没有这份声明的结果直接丢弃重派。

派子代理的提示词模板：

```text
【硬性禁令】只能用 Read 工具看图。禁止使用/安装任何 OCR 或文字识别工具与模型（tesseract、pytesseract、easyocr、paddleocr、Umi-OCR、系统 OCR API…），禁止 pip/uv/apt 安装任何包，禁止对图片做旋转、裁剪、缩放、增强、拼接等加工，禁止创建/修改/删除任何文件。
【读不到就停】Read 打不开或图片模糊到无法辨认时，立即停止并如实说明，不要寻找替代方案。
【先声明】报告开头列出：本次用 Read 实际打开的文件清单 + 未能打开的文件。

用 Read 工具查看这些教材照片（主代理已做方向校正与缩放）：
/tmp/batch/IMG001.jpg … /tmp/batch/IMG005.jpg

这是《工程数学基础》第2章"矩阵"的正文照片。任务：
1. 逐页忠实转录印刷正文为 Markdown（中文照抄，公式用 LaTeX），保留原编号（定义 2.x、例 2.x、表 2.x）。
2. 每页先报告右上角页码和所属节号。
3. 矩阵、例题解答、MATLAB 命令与屏幕输出原样保留。
4. 看不清、被手指遮挡或反光处标"〔待核对〕"，不要猜补；学生手写旁注单独列出、不混入正文。
5. 需要逐字核对的记号：化简箭头上下的行变换标注（如 -4r₂+r₁ 的下标）、矩阵元素正负号。
```

## 登记教材照片（原件不入库）

- **图片二进制不入库**：教材照片由拍摄者本地保存，仓库里不放 `.jpg`/`.heic`。不重命名、不转格式、不压缩原件。
- 在 `课程/<课名>/原始资料/index.md` 里**逐张**登记：文件名、原书页码、主要内容、SHA-256；文件名写成**纯文本，不加链接**（否则会变死链）。
- 登记完必须逐张核对哈希（登记值 = 本地原件）：
  ```bash
  python3 - <<'PY'
  import hashlib, re; from pathlib import Path
  md = Path('课程/工程数学/原始资料/index.md').read_text(encoding='utf-8')
  reg = {m.group(2): m.group(1) for m in re.finditer(r'^([0-9a-f]{64})  (\S+)$', md, re.M)}
  ext = Path('工程数学')  # 拍摄者本地原件目录
  bad = [n for n, h in reg.items()
         if not (ext / n).exists() or hashlib.sha256((ext / n).read_bytes()).hexdigest() != h]
  print(f'{len(reg)} 条登记，{len(bad)} 条不符/缺失', bad[:5])
  PY
  ```
- 读图前用 `.githooks/prepare-photos.py` 从**仓库外原件**生成 `/tmp` 阅读副本（HEIC→全分辨率 PNG）再派子代理读；副本不入库。
- 新增**文本类**原始资料（如转写）才需要 `.gitignore` 白名单 `!/完整相对路径`；图片一律不加。

## 写教材解析（先抄后析）

- **一节一个文件**，放 `课程/<课名>/教材解析/第NN章-章名/`，命名 `第NN章-<节号>-<节名>.md`。不要把整章塞进一个文件。
- 文件内部固定两段：先**原书抄录**（按页码抄印刷正文与原编号），紧跟**解析**（概念、成立条件、推导、例题解法、易错点、验算）。教材陈述与整理者补充分开标注。
- 写完必须**独立验算**：用精确有理数运算把例题、习题的数值结果重算一遍，不照抄书上手写过程。这一步经常抓到错：

  ```python
  from fractions import Fraction as F
  # 自己写 mul/det/rank/inv，全部用 Fraction，避免浮点掩盖错误
  ```

  验算发现差异时，改解析里的数值并把结论写进「本节完成边界」。
- 学生手写答案不是标准答案；教材习题不自动认定为教师布置的作业。
- 每个文件末尾写「本节完成边界」：已抄录/已解析/〔待核对〕/未完成，不夸大。

## 新增一门课程

1. 建 `课程/<中文课名>/` 及五个类别子目录。
2. 每类从 `模板/` 复制对应模板生成 `index.md`；课程入口复制 `模板/课程索引.md`。
3. 在 `课程/index.md` 登记这门课，在 `.gitignore` 逐个加白名单。
4. 跑下面的收尾检查再提交。不需要改 README 正文、维护细则正文或钩子脚本——自动区块会自己反映新课程。

## 收尾固定动作（每次编辑后都跑）

```bash
python3 .githooks/update-readme.py --worktree   # 同步 README 目录 + 维护细则状态区块
python3 .githooks/check-markdown.py             # 美观度，错误必须为 0
python3 .githooks/test-update-readme.py         # 集成测试，必须全绿
git fsck --no-progress                          # 仓库对象完整性，不应有输出
git diff --check                                # 空白与冲突标记
```

四项通过再提交。README 的课程目录和 `维护细则.md` 的状态区块都是**自动生成的**：pre-commit 每次从暂存内容重算，pre-push 校验一致性——所以提交前不要手工改这两块的内部内容。

## 常见故障

- **`git fsck` 报对象损坏**（`inflate: data stream error`）：先确认工作区文件与源文件哈希一致，再删掉损坏的松散对象 `.git/objects/xx/…`，重新 `git add` 该文件，重跑 `git fsck`。不要用 `git gc` 掩盖。
- **提交被 pre-commit 拦下**：按提示修命名、索引链接或自动区块；不要用 `--no-verify` 绕过，推送端仍会拦。
- **主对话读图超限**：改派子代理，或把剩余张数留到下一轮对话。
- **链接失效**：`validate` 只认本地相对链接；新增、移动、删除资料后要同步更新对应类别的 `index.md`。

## 检查清单

提交前逐项确认：

- [ ] 新文件都进了 `.gitignore` 精确白名单，没有通配符。
- [ ] 每份新资料都在所属类别的 `index.md` 里有链接。
- [ ] 教材照片：字节未变、SHA-256 已登记、页码映射准确。
- [ ] 教材解析：抄录与解析分开、页码标注、数值已独立验算、完成边界如实。
- [ ] 图片是子代理**用 Read 真看**的：不是 OCR 读数，也没被 OCR、旋转裁剪或任何图像加工工具"代读"。
- [ ] 收尾五项全过，工作区干净。
