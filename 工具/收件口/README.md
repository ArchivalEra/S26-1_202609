# 收件口（把手机上的文件传进本机）

用户在外时，把教材照片 / 转写 / 素材从手机传进这台机器的临时通道。**只写不读**：除上传表单外不提供任何读取接口，
token 就是唯一门槛，用完杀掉进程即可。

## 开一次

```bash
# 1) 本机起收件口（token 随便取、每次换一个；端口挑没人占的）
python3 工具/收件口/recv_server.py <token> 8801
#    收到的文件默认落到 工具/收件/（该目录内容默认不入库）

# 2) 另开一个终端，把本地端口曝到公网
ssh -p 443 -o ServerAliveInterval=30 -o ExitOnForwardFailure=yes \
    -o ProxyCommand='socat - PROXY:127.0.0.1:%h:%p,proxyport=2080' \
    -R 80:localhost:8801 serveo.net
#    输出里 https://<随机串>.serveousercontent.com 就是手机要打开的域名
```

手机打开 `https://<那个域名>/u/<token>/`，选文件、点上传。页面**自动切 2 MB 分片**逐片发，
大文件（整本教材照片、压缩包）不会因为隧道截断而失败；进度显示「全部结束」才算成功。

## 两个坑（都实弹踩过）

0. **表单页必须回 `text/html`**：给所有响应统一回 `text/plain` 会把上传页的源码当正文印在浏览器里
   （手机上看着就是「收件口出错了」）。`do_GET` 那处已固定成 `text/html`，别改回去。
1. **别把收件目录或日志放 `/tmp`**：本机 `/tmp` 是 tmpfs，会话重启即空——脚本、日志、收到的文件一起没，
   于是隧道指向一个没人监听的口，返回 **502**。这个脚本默认落到 `工具/收件/`。
2. **「在不在跑」按端口验**：`ss -tln | grep :8801`。不要用 `pgrep -f recv_server.py`——
   `-f` 匹配整条命令行，会把你**正在跑的那条命令自己**匹配上，给出「已在跑」的假象。

还有一个**给手机用户的提醒**：serveo 免费隧道会在浏览器里先插一页 **"Serveo Browser Warning → Continue to Site"**，
**点一下才能进上传页**（curl 不带浏览器特征，所以本机回环测试看不到这页，别被它骗过——手机没到过收件口，
日志里会一条请求都没有）。

顺带：本机解析不了外网域名（DNS 坏），所以 ssh 必须挂上面那条 `ProxyCommand` 走 2080 的 HTTP 代理；
serveo 免费隧道每次重启换一个域名，换域名不影响收件口本身。

## 收到之后

按材料类型**归位**，别把原件堆在收件目录里：

- 课堂材料（转写、照片）→ `课程/<课>/原始资料/`，按规约登记（文件名、页码/覆盖范围、SHA-256），加白名单；
- 工具、脚本、可复用的东西 → `工具/`；
- 归位后清掉收件目录里的副本（`工具/收件/` 内容默认不入库，留着也不会被提交，但容易看混）。

用完**杀掉两个进程**（收件口与 ssh），别长期开着写入口。
