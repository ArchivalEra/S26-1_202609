# 查学习通作业（拉清单 → 抓题面 → 取图）

2026-11-03 首次跑通并记录；**2026-11-05 改成「浏览器内扫码登录 + 页面内请求」**（见 §零）。
**目的是「这门课还有什么没做」和「题面原文是什么」**，不是模拟登录。

## 零、推荐路径：扫码登录 + 浏览器内请求（2026-11-05 起用这条）

### 为什么换掉「读 SQLite 拿 Cookie」

旧做法是 `cp` 出 Zen 的 `cookies.sqlite` 再拼 Cookie 串。两个问题：

1. **依赖特定浏览器装了什么、登的是哪个域**。2026-11-05 实测：Zen 里 1290 条 Cookie，
   `.chaoxing.com` 只有 3 条（`fid`／`xxtenc`／`web_uname`），**没有 `UID`／`_uid`** ——
   因为当时登的是**学校门户**（`.dayainfo.com`，浙江水利水电学院 17 条含 `s` 会话），
   门户登录态**不生成** `chaoxing.com` 的凭据。查了 chromium／chrome／firefox-esr，chaoxing 全 0 条。
2. **它等于把用户的会话凭据读出来**。能跑通是因为本机明文落盘，不该当成常规手段。

### 新做法（凭据全程不离开浏览器）

1. 用 ZCode 应用内浏览器开 `https://passport2.chaoxing.com/login`；
2. 页面上有 180×180 的扫码登录图（`img[src*="createqr"]`，src 形如
   `https://passport2.chaoxing.com/createqr?uuid=…&fid=-1`）。**把它取出来给人扫**：
   ```js
   // 应用内浏览器里 evaluate：把二维码转 dataURL 存盘再发图
   const url = document.querySelector('#qrloginimg, img[src*="createqr"]').src;
   const b = await (await fetch(url, { credentials: 'include' })).blob();
   // FileReader → dataURL → 解 base64 写 /tmp/chaoxing-qr.png
   ```
   ⚠️ `tab.screenshot()` 在这个环境**会超时**（`surface preparation timed out`），
   取图要直接读 `<img>` 的字节，不要截屏。
3. 人用**手机学习通 App** 扫码；登录成功后页面自己跳到
   `https://i.mooc.chaoxing.com/space/index?ws=1&t=…`，标题变成学校名（如「浙江水利水电学院」）。
4. **拉数据不要在 `i.mooc` 页面里 `fetch` `mooc1-api`**——跨域，`Failed to fetch`（CORS）。
   正确做法：**在这个浏览器里新开标签、直接 `goto` 接口地址**（同源导航不受 CORS 限制）：
   ```
   https://mooc1-api.chaoxing.com/work/stu-work?vx=0
   ```
   打开后 `document.querySelectorAll('li[data]')` 就是作业条目，
   `document.body.innerText` 里是「作业名 / 状态 / 课程 / 剩余」的可读文本。
   2026-11-05 实测：`HTTP 200`、36,136 字节、**39 条**。

### 判据（什么时候该怀疑登录态）

| 现象 | 含义 |
| :--- | :--- |
| `goto` 后被跳到 `passport2.chaoxing.com/login` | 未登录／凭据不在该浏览器 |
| 页面标题变成学校名 + URL 含 `i.mooc.chaoxing.com/space/index` | 登录成功 |
| `li[data]` 计数 > 0 | 清单拿到了 |

## 一、旧做法：从 Zen 读 Cookie（保留作对照，不再首选）

> 这条能跑通的前提是：**Zen 里真的登过学习通主站**（不是学校门户）。
> 2026-11-03 那次是 10 条齐全；2026-11-05 就只剩 3 条了，所以别默认它可用。

Cookie 在 **Zen 浏览器**（`~/.config/zen/<profile>/cookies.sqlite`）里，不在 Chrome/Chromium/ZCode 里。
值是 FireFox 系 SQLite 格式（明文，不用解 Chromium 的加密）：

```bash
cp "/home/archivalera/.config/zen/r63zt1xu.Default (release)/cookies.sqlite" /tmp/zen.db
cp "/home/archivalera/.config/zen/r63zt1xu.Default (release)/cookies.sqlite-wal" /tmp/zen.db-wal 2>/dev/null
python3 -I -c "
import sqlite3
c = sqlite3.connect('/tmp/zen.db')
rows = c.execute(\"select name, value from moz_cookies where host like '%chaoxing%'\").fetchall()
print('; '.join(f'{n}={v}' for n, v in rows))
" > /tmp/ck.txt
```

实测拿到 10 条：`_d`、`UID`、`_uid`、`fid`、`uf`、`vc3`、`xxtenc`、`cx_p_token`、`p_auth_token`、`DSSTASH_LOG`。
**`UID` 与 `_uid` 是关键**（缺任一条会被转到登录页）。

> ⚠️ `cookies.sqlite` 在浏览器**运行时会锁住**，必须先 `cp` 出来再读，直接连会 `database is locked`。
> ⚠️ 只拷主库可能漏掉刚写的 Cookie（在 `-wal` 里没 checkpoint）——**三个文件（`-wal`／`-shm`）一起拷**。
> ⚠️ 先查**登的是哪个域**：`select host,count(*) from moz_cookies group by host`。
> 只有 `.chaoxing.com` 下出现 `UID`／`_uid` 才算登了主站；`.dayainfo.com` 那套是**学校门户**，不能用。

## 二、拉作业总列表

```
GET https://mooc1-api.chaoxing.com/work/stu-work?vx=0
  Header: Cookie: <上面那串>
          User-Agent: Mozilla/5.0 (X11; Linux x86_64) Firefox/145.0
          Referer: https://mooc1-api.chaoxing.com/
```

**返回是 HTML（不是 JSON）**，约 32 KB。判据：
- `<title>作业列表</title>` 且不含「登录」⇒ Cookie 有效；
- 返回登录页 ⇒ Cookie 失效，重取。

### 解析（2026-11-03 实测的结构）

每个作业是一个 `<li onclick="goTask(this);" data="https://…&taskrefId=…&courseId=…&clazzId=…&enc_task=…">`。
**状态有两种写法，必须统一走 `aria-label`**：

```python
import re, html
s = open('stu-work.html', encoding='utf-8').read()
items = []
for m in re.finditer(r'<li[^>]*data="(https://mooc1-api[^"]+)"[^>]*>([\s\S]*?)(?=<li[^>]*data=|<div id="footer"|</ul>)', s):
    url, body = m.group(1), m.group(2)
    lbl  = (re.search(r'aria-label="作业名称([^"]+)"', body) or [None, ''])[1]
    name = re.search(r'<p[^>]*>([^<]*)</p>', body)
    st   = re.search(r'作业状态([^所]+)所属课程', lbl)      # ← 唯一可靠的状态来源
    crs  = re.search(r'所属课程([^剩]+)', lbl)
    q    = dict(re.findall(r'([a-zA-Z_]+)=([^&]+)', url))
    items.append({
        '作业': html.unescape(name.group(1).strip()) if name else '?',
        '状态': st.group(1).strip() if st else '',        # 未提交 / 已完成 / 待批阅
        '课程': crs.group(1).strip() if crs else '?',
        '剩余': (re.search(r'剩余(.+)$', lbl).group(1) if '剩余' in lbl else ''),
        'courseId': q.get('courseId'), 'clazzId': q.get('clazzId'),
        'taskrefId': q.get('taskrefId'), 'enc': q.get('enc_task'),
    })
```

**为什么不能用 `class="status"`**：只有「未提交」那条带这个 class；
「已完成」是**裸 span**（`<span aria-hidden="true">已完成</span>`），
按 class 抓会漏掉一半条目（实测 35 条里 16 条状态为空）。

## 三、抓题面

总列表只是元信息（题目数量、截止时间）。题面要两步：

```
① GET  https://mooc1-api.chaoxing.com/mooc-ans/android/mtaskmsgspecial?taskrefId=…&courseId=…&clazzId=…&type=work&enc_task=…
        ← 12 KB 骨架页，只有「共包含 N 道题目」

② 从 ① 的 HTML 里抽 /work/phone/doHomeWork?… 链接，再 GET
        ← 92 KB，含全部题面文字与图片 URL
```

```bash
# ① 抓骨架页
curl -s -H "Cookie: $CK" -H "User-Agent: $UA" "$MTASK_URL" -o detail.html
# ② 抽真题页链接并抓
URL=$(grep -oE '/work/phone/(doHomeWork|task-work)\?[^"'"'"' ]+' detail.html | head -1)
curl -s -H "Cookie: $CK" -H "User-Agent: $UA" \
     "https://mooc1-api.chaoxing.com/mooc-ans$URL" -o q.html
```

题面文本：去掉 `<script>`/`<style>` 后按标签切行，从「简答题 / 单选题 / 论述题」那行往后读。

## 五、图分辨率不够时的替代源

教材 docx 内嵌的图通常比平台清晰。第 8 章那本 docx 里：

```bash

xml = z.read('word/document.xml').decode('utf-8')
```

## 六、已知的坑

| 坑 | 表现 | 处置 |
| :--- | :--- | :--- |
| `class="status"` 只覆盖一半 | 状态字段大量为空 | 走 `aria-label` |
| 总列表解析用 `goTask\(this\)` 精确匹配 | 0 条 | 只匹配 `<li … data="https://mooc1-api…` |
| 平台图 555×334 | 接线细节读不出 | 改从教材 docx 抽 |
| 附件「仅支持打开 N 次」 | 详情页显示「已过时效，不能操作」 | 那条通常是已提交待批阅，不用抓题 |
| `cookies.sqlite` 被锁 | `database is locked` | 先 `cp` 再读 |
| Cookie 在 Zen 不在 Chrome | Chrome/Chromium/ZCode 里 0 条 chaoxing | 固定查 Zen 的 profile |

## 八、推荐路径（2026-11-13 起用：真实浏览器 + WebBridge，接口直取作业详情）

> 零 / 五两节的 Zen-cookie 流程是**备胎**。主战场在 kimi 的真实浏览器：
> 用户浏览器开 `https://www.chaoxing.com/`（已登录），agent 用 Kimi Browser Extension
> （WebBridge，`http://127.0.0.1:10086/command`）驱动。它有 `evaluate`，能读页面属性、
> 发接口请求——这是内置浏览器做不到、之前卡死的地方。

### 8.1 三步拿到「真实作业页 URL」（2026-11-13 实测）

```
① 拉作业列表（H5 页，只给清单，不给题面）
   navigate → https://mooc1-api.chaoxing.com/work/stu-work?vx=0

② evaluate 提取目标作业的 <li data> 属性 —— 参数全在这里
   const items = [...document.querySelectorAll("li[data]")]
                 .map(li => ({ name: li.innerText, data: li.getAttribute("data") }));
   例（客观题--变压器训练用，56 题）：
   data = https://mooc1-api.chaoxing.com/mooc-ans/android/mtaskmsgspecial
          ?taskrefId=58075489&msgId=0&courseId=249967970&userId=账号ID_已打码
          &clazzId=154248884&type=work&enc_task=fa439ef2f1b7873999ba5d183f6d9e16

③ 骨架页 mtaskmsgspecial 会**自己跳转**到真实作业页：
   navigate → 那个 data URL
   页面地址栏变成（key 是 task-work，不是 doHomeWork）：
   https://mooc1-api.chaoxing.com/mooc-ans/work/phone/task-work
     ?taskrefId=58075489&courseId=249967970&classId=154248884&userId=账号ID_已打码
     &role=&source=0&enc_task=fa439ef2f1b7873999ba5d183f6d9e16
     &cpi=564185913&vx=0&fromGroup=0
   read_page 即得「共包含 56 道题目，其中单选题 36 道、多选题 4 道、判断题 16 道」
```

**要点**
- **作业详情绝对不能点出来**——H5 列表的 `<li>` 点击走 `goTask()` 且依赖 jsbridge，
  内置浏览器永远跳不了；只有从 `data` 属性读参数、拼接口 URL 才行。
- `mtaskmsgspecial` 是骨架页（只含统计），访问后 **302 到 `task-work`** 才是真题页。
- **参数名 `classId`（不是 `clazzId`）**在 task-work URL 里；`clazzId` 是列表 data 里的名字，
  拼 URL 时别抄错。
- `userId`、`cpi` 都可从 data/跳转 URL 拿；跳转自动带 `cpi`，手拼时留空也行（页面自己补）。

### 8.2 从真实作业页提取题目（下一步）

页面容器是 `DIV.zwork` + `DIV.zwork_info`，题型在「共包含 N 道」里给出；
题目本体加载后是 `li` 列表。用 `evaluate` 逐题抽文本/选项/图 URL，
再与本地 `课程总览/<课>/作业/*.md` 对照、走三道内容闸入库。
