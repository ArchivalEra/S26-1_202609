# 16: 全站符号系统收口为深模块（一棵纯语义核心 + 四块薄投影适配器）

**What to build:** 推翻「只挪 `build.mjs` 胶水」的浅模块思路，将自 2026-09-20 起历次打补丁膨胀、至今在 **OKF v0.2 元数据 / HTML 站点（公式·正文·图元·运行时）/ `/machine/`（含 `Birthright.html`）/ WebMCP / 本地 `工具/mcp-端点/`** 五个正交面分裂的符号机制，彻底收口为**一棵纯语义深核心（`站点/symbols/`）+ 四块薄投影适配器**，同步修掉核查出的 4 处潜伏断链。

## 一、实测确诊的结构病灶与潜伏断链

1. **正交分裂导致「五套符号逻辑」**：`站点/符号环境.mjs`、`站点/plugins/prose-terms.mjs`、`站点/math/terms.mjs` + `render.mjs`、`站点/plugins/figures.mjs`、`站点/plugins/webmcp-tools.mjs`、`工具/mcp-端点/lib/packs-source.mjs` 与 `站点/build.mjs`（~260 行胶水）各自解析或拼接词条。
2. **公式 `符号强制` 已断链（潜伏 Bug #1）**：`站点/build.mjs:1417,1469` 解析了 `frontmatter['符号强制']`（`glossaryPins`），传给 `pageMathEnv` 时却硬编码 `forceTerm: {}`；且 `站点/math/terms.mjs:156-160` 用节点源切片 `src.slice(...)` 查 `force` 并返回 `{ pack: direct, entry: direct }`（把包名误当成词条名）。
3. **两套门牌号与三处手拼 `<a>`（潜伏 Bug #2）**：公式产物 `data-term` 写 `包:词条`（`math/render.mjs:34`），正文同包词条写裸 `词条`（`prose-terms.mjs:356`），图元 `figures.mjs:2269,2335` 只查 `pageTexDict[label]` 绕开 `符号强制`/跨包 `包:id`，且 `restoreFigures` 兜底引用了未定义的 `glossHref`。
4. **OKF v0.2 与 MCP 双路径分裂（潜伏 Bug #3）**：
   - `工具/mcp-端点/lib/read-core.mjs:234-246` 用单行标量正则 `parseFrontmatter`，丢弃 OKF v0.2 的 `符号排除` 列表与 `符号强制` 映射；
   - `工具/mcp-端点/lib/packs-source.mjs:65-74` 不读 `:::glossary-match`，且缺省 `course` 时用 `merged.set(id, ...)` 静默覆盖不同包的同名 `id`（违反自身「并列返回」注释）；
   - `站点/plugins/webmcp-tools.mjs:61,2127-2176` 声明了 `glossaryJson: 'sym-glossary-json'` 却从不读取，`site_show_symbol` 每次滚动 + 派发点击 + 等 `250ms` 反爬 DOM（丢失独立义项 `ctx`，且只读查词被迫标为 `readOnlyHint: false`）。
5. **`/machine/` 符号上下文清零与死壳残留（潜伏 Bug #4）**：
   - `站点/build.mjs:3026-3029` 生成 `/machine/<page>.json` 时剥掉 frontmatter 却保留原始 `[B]{#电机学:sym-B}` 与 `:::figure`，`Birthright.html` 未暴露课程包链（如「工程数学不套通用包」「电路用 `通用+电路原理`」）；
   - 运行时脚本名仍沿用旧名 `assets/plugins/math-glossary.js`，CSS 与 4 份 JS 仍各自复制 `SYMBOL_SELECTOR` 且保留已退场的 `.ML__latex [data-term]`；统计闸门 `symbol-coverage.mjs` / `symbol-gaps.mjs` 仍靠产物 HTML 正则逆向猜测。

## 二、目标架构：深核心 `站点/symbols/` + 四块薄适配器

### 1. 深核心 `站点/symbols/`（纯数据与纯语义判定：零 DOM、零 KaTeX、零传输）

对外仅暴露 **3 个窄接口**，内部吞掉 YAML/OKF 解析、围栏解析、包链合并、正则防呆、`compileDictionary`、唯一规范键与三路判定原语：

1. **`createSymbolCatalog({ root, parseMath })`**：
   - 共用同一套完整 YAML/OKF v0.2 frontmatter 解析器（识别 `id`、`course`、`符号强制`、`符号排除`、`符号排除公式`）；
   - 解析 `SYMBOL_PACKS` 页中的 `:::glossary-dict` 与 `:::glossary-match`，统一归一化为**全站唯一规范键 `包:词条`**（`Canonical Key`），内部编译形状键与正则模式索引。
2. **`catalog.lookup({ key, id, q, form, course, pack })`**：
   - 统一查词接口：支持规范键精确命中、`glossary-match` 词形反查、`course` 包链优先级覆盖、缺省 `course` 时多包并列返回（不再覆写）、并携带各义项 `ctx` 与 `isCurrentCtx`。
3. **`catalog.openPage({ relPath, frontmatter }) → session.finalize()`**：
   - 单一页面会话：整合 `BUILD_PHASES` > `COURSE_ENV` / OKF `course`、`符号强制`、`符号排除`、`符号排除公式`；
   - 统一提供公式 IR 判定（修复 `forceTerm` 按词条 id 强制锚定到目标包）、正文取词（修复 `@@MATH_INLINE_n@@` 透传补丁）、图元符号解析（支持 `包:id` 与 `符号强制`，彻底移除 `figures.mjs` 的 `glossHref` 漏洞）；
   - `finalize()` 输出不可变 **`PageSymbolBundle`**：`{ env, ctx, pins, exclusions, terms, hits, matchedForms, diagnostics }`。

### 2. 四块薄投影适配器（与核心在同一接缝对齐）

1. **HTML 构建与浏览器运行时 Adapter**：
   - 注入 `renderTex` 将 `PageSymbolBundle` 投影为唯一锚点模板 `<a class="sym-gloss" data-term="包:词条">...</a>`、总表 `<table>` 与 `#sym-glossary-json`（同时携带供人看的气泡 HTML 与供 WebMCP 直读的纯文本/义项结构）；
   - 收正产物脚本名（淘汰 `math-glossary.js` 旧名并同步 `spa-router`、`shirone-reader.css`、`hook_lib.py`），统一选择器单源生成并清理已退场的 `.ML__latex [data-term]` 死分支；
   - `symbol-coverage.mjs` / `symbol-gaps.mjs` 直接消费 `PageSymbolBundle` 事实统计，测试层仅做 `dist` HTML 独立一致性复核（取消 `10%` 反推猜测容差依赖）。
2. **`/machine/` & `Birthright.html` Adapter**：
   - 从 `catalog` 导出结构化符号表 `/machine/symbols/index.json`（含包注册与 `COURSE_ENV`/`BUILD_PHASES` 包链规则）与 `/machine/symbols/<pack>.json`，并在 `Birthright.html` 显式挂出直达入口；
   - 为每页 `/machine/<page>.json`（含超长切片 `_index.json`）附加本页预解析的轻量 `symbols` 上下文（`{ env, ctx, pins, exclusions, termKeys }`），不依赖外部模型自拼规则。
3. **WebMCP Adapter（`站点/plugins/webmcp-tools.mjs`）**：
   - `site_read(what="symbols")` 与 `site_show_symbol` **默认直读 `#sym-glossary-json`**（升级为纯只读幂等工具 `readOnlyHint: true`，返回含规范 `key`、完整义项 `ctx` 的结构化数据，与 `course_symbol` 对齐），仅在显式请求交互高亮时才触发气泡 UI 点击。
4. **本地 MCP Adapter（`工具/mcp-端点/`）**：
   - `packs-source.mjs` 与 `read-core.mjs` 改调 `createSymbolCatalog` 与共享 YAML/OKF frontmatter 解析，使 `course_symbol` / `course_read_page` / `course_ask` 与站点渲染、`WebMCP`、`/machine/` 完全同源。
