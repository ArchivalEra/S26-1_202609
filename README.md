# 学期学习仓库总入口

本仓库是 **2026 年秋季学期统一学习仓库**，以中文课程名作为主分类，每门课独立管理作业、教材解析、课堂笔记、原始资料和音频下载记录。资料沿用 **Open Knowledge Format（OKF v0.2）** 元数据结构，中文优先，不强行更改已有稳定 ID。目前**只有“工程数学”课程已确认**，其他课程待课程表或正式资料提供后按模板扩展；历史领域目录不是真实课程清单。

## 仓库结构

- `课程/`：本学期正式课程资料，入口为[课程总索引](./课程/index.md)。
  - `课程/<中文课名>/`：一门已确认课程，含五类固定子目录：
    - `作业/`：正式布置的作业记录；
    - `教材解析/`：按“版本—章—节”组织的整本教材解析；
    - `课堂笔记/`：按上课日期整理的课堂笔记；
    - `原始资料/`：原始转写与讲义等原始文件；
    - `音频/`：音频下载链接与元数据记录。
- `模板/`：各类资料的 [OKF 模板](./模板/课程索引.md)（课程索引、作业、教材章节解析、课堂笔记、音频记录）。
- `knowledge/`：改版前的知识库入口，仅保留[迁移说明](./knowledge/index.md)供旧链接兼容；正文已迁入课程目录，不再平行维护。
- `.githooks/`：提交检查、README 自动同步与推送检查。
- `Original/`：旧仓库原始资料根目录的历史位置；新原始资料一律放对应课程目录。

## 整理与命名约定

1. 课程目录使用 `课程/<中文课名>/<类别>`；日期类资料（作业、课堂笔记、音频记录）命名为 `YYYY-MM-DD-名称.md`；**教材解析一节一个文件**，放在章目录 `教材解析/第NN章-章名/` 下，命名为 `第NN章-<节号>-<节名>.md`，不把整章塞进一个 md；各类目录入口为 `index.md`。
2. 笔记保留 OKF v0.2 元数据与稳定 ID，中文记录，不要求中英双语成对；新增模板补充课程、资料类别及来源信息。
3. 原始资料不等于知识笔记：筛选、合并、规范化后沉淀概念、方法和易错点；转写口误、缺失板书与题目条件不猜补，整理者补充与原文陈述明确区分。
4. 教材解析按“教材版本—章—节”组织，不按课堂日期拆散教材体系。每个解析文件先写**原书抄录**（按原书页码抄录印刷正文与原编号），紧跟**解析**（概念、条件、推导、例题解法、易错点、验算），先抄后析。目录已确认的章节才登记，看不清的照片处标“待核对”，不得虚构书名、章节或解析进度。
5. 作业只登记经正式通知确认的题目；课堂例题、旧笔记中的教材习题不自动认定为正式作业，题号与截止时间以学习通等正式来源为准。
6. 原始资料与课堂发言可能包含个人信息，提交或推送前检查是否适合公开；不把登录令牌、密码、Cookie 等凭据写入仓库。

## 音频资料边界

音频目录默认**只保存链接与元数据**：不自动下载、不提交音频二进制、不向外部服务上传课堂内容。每条记录必须包含课程、上课日期、准确课次/节次（附核实来源）、主题、下载链接及其来源与有效期、关联课堂笔记和原始转写；同一课多个片段分别登记起止时间与时间基准。尚未提供的链接标为“待提供”，不编造地址，不凭日期或文件名推断课次。

## 新增课程与资料流程

1. 从[课程索引模板](./模板/课程索引.md)创建 `课程/<中文课名>/index.md`，并按模板建立五类 `index.md`。
2. 每个新文件复制对应模板，填写唯一稳定 ID、课程、类别与来源，保持相对链接互链。
3. 在 `.gitignore` 的精确白名单中为**每个新文件**添加 `!/完整相对路径`（不得使用通配符）。
4. 更新课程总索引与课程入口；运行下方 CLI 验证命令确认 README 目录可正常同步。
5. 提交前由 hook 校验命名与白名单，README 自动区块由 hook 从暂存区生成；正式提交、推送由主流程执行。

## 提交时自动同步 README

新克隆仓库后执行一次 `git config core.hooksPath .githooks`，并确保安装 Python 3。当前本地仓库已启用该配置。

每次正常 `git commit`，`pre-commit` 先检查现有命名与白名单规则，再从**暂存区**生成下方自动目录，自动暂存 README。README 若有未暂存修改，提交会停止，需先自行暂存或保存这些修改。`--no-verify` 可绕过本地 hook，因此它不等同于服务端强制规则。

常用 CLI 验证命令：

```bash
python3 .githooks/test-update-readme.py
python3 .githooks/update-readme.py --worktree   # 直接写入工作区 README，不自动暂存
python3 .githooks/check-markdown.py              # Markdown 美观度与可读性检查
git config core.hooksPath .githooks
```

`--worktree` 只更新工作区 README，不自动暂存；推送时仍要求索引同步。新克隆仓库需先执行 `git config core.hooksPath .githooks` 启用钩子，再运行上述验证命令。
