# 静态阅读站前端交接词

本文件是给**前端实现 agent** 的**可直接粘贴的提示词**。把它整段发给对方（连同仓库访问权限）即可开工。完整方案见[前端实现计划书](./前端实现计划书.md)。

## 一、直接粘贴给对方的内容

```text
【任务】把 /mnt/hdd/zcode-projects/GONGCHENGSHUXUE20260917 这个中文课程仓库
做成一个纯文本＋公式的静态阅读站，经反向代理提供给中国大陆用户
（该仓库直连 GitHub 基本不可用，你负责反代）。

【先读】仓库里的 `站点/前端实现计划书.md` 是完整方案与验收标准，务必先读。
其中 §3 是关键：全仓 1,859 个公式的兼容性风险清单，逐条给了真实文件与行号。

【硬约束】
1. 网页不含任何图片。仓库里的教材照片已全部退库（不在仓库内），
   正文中指向 .jpg/.heic/.doc 的链接一律降级为纯文本，不留死链。
2. 公式解析顺序必须是：代码围栏 → 数学 → 链接/强调。
3. 渲染管线自选：KaTeX / MathJax / 多解析器并存 / 按文档特征分派，
   都行，只要最终零报错。最高危的是数学模式内的裸中文
   （KaTeX 会 parse error，MathJax 可渲染）。
4. 离线自持：渲染器的 JS/CSS/字体全部随仓库提供，禁止引用
   unpkg / jsdelivr / cdnjs，做到浏览器除同源外零请求。
5. 必须能在任意子路径（如 /repo/）下工作：资源用相对路径，
   禁止绝对路径 /assets/...，不建议 <base href>。
6. 仓库用精确白名单：你新增的每个文件都要在 .gitignore 加一行
   `!/完整相对路径`，禁止通配符、不能只放行目录。
7. 构建产物不入库；只提交源码与手工资产（如 KaTeX 字体）。
8. 不要改 `课程/**` 的正文内容；不要动 README 与 维护细则.md 的
   自动区块（AUTO-CATALOG / AUTO-MAINTENANCE），它们由钩子重算。
   要加站点入口请加在区块之外的正文，或先与维护者协商。
9. 不要用 git --no-verify 绕过钩子。

【验收】按计划书 §8 逐条自检：公式零报错、7 处 \tag 编号可见、
沙路法则数组竖线可见、126 处行内矩阵未被拆行、宽表与超长公式不破版、
无死链、除同源零请求、任意子路径正常、构建可离线可重复。

【交付说明】请写明：渲染器选型与版本、依赖清单、构建命令、
资源目录结构、反代需配合的点（基路径、MIME、末尾斜杠行为）。
```

## 二、给维护者（本仓库）的对接要点

- **不要**把站点构建产物提交进本仓库；产物目录应被忽略。
- 对方若要求把站点入口写进 README，加在 `AUTO-CATALOG` 区块**之外**的正文，或按其流程先协商。
- 对方新增的每个文件都需要白名单条目；提交后由 pre-commit 重算两处自动区块，`pre-push` 会校验。
- 验收时按[维护细则](../维护细则.md)第 1 节的五项命令跑一遍，确认仓库本身仍干净。
- 本仓库的数学内容与〔待核对〕项由维护者负责；对方只报告与渲染无关的内容问题，不直接修改正文。
