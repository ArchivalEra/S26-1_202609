# 数学可视化需求计划书

**目的**：给《工程数学基础》的解析配上数学图形与动画，让专科学生看懂"公式在说什么"。本文件分两部分：**第一部分是交给工具调研者的需求书**（可直接复制转交），**第二部分是对是否引入 Astro 的评估与建议**。

站点现有实现见[前端实现计划书](./前端实现计划书.md)；仓库规则见[维护条例](../维护条例.md)。

---

## 第一部分：交给调研者的需求书（可直接复制）

```text
【任务】为《工程数学基础》课程解析站点寻找或选定「数学图形/动画自动生成方案」，
并交付一个可复现的生成流程。

【背景】站点是把 Markdown 教材解析渲染成的静态阅读站：
- 构建：纯 Node 脚本（站点/build.mjs，747 行，无框架）→ 静态 HTML
- 公式：KaTeX 自持（20 个 woff2 字体入库）
- 部署：GitHub Actions → EdgeOne，挂在子路径 /repo/S26-1_202609/ 下
- 已有 239+ 公式的第 1、2 章解析，学生反馈"公式看不懂几何意义"

【硬约束（必须满足，否则接不进来）】
1. **输出静态资源**：SVG 优先，其次 GIF/MP4。不接受需要浏览器端 JS 运行时
   才能渲染图形的方案（如 MathBox、D3、JSXGraph 运行时渲染）。
2. **构建期生成**：生成发生在构建机上。生成脚本入库，产物入库或构建时产出，
   但**不允许运行时访问任何 CDN**（站点必须离线可用，国内直连 GitHub/CDN 不可靠）。
3. **跟随深浅主题**：图形颜色应能随站点主题（浅色/深色）变化。SVG 用
   CSS 变量（fill="var(--primary)"）最理想；若用位图则需两套或接受不随主题。
4. **中文与数学共存**：图形里可能要标中文（如"第 i 行"）与数学符号，
   需支持中文文本渲染或允许我们后期叠加。
5. **体积可控**：单个图形建议 < 200KB；整站新增总量建议 < 5MB。
6. **可复现**：给出精确的依赖版本与生成命令，能在 clean 环境重跑。

【优先覆盖的内容（按已解析章节，按价值排序）】
- 行列式的几何意义：二阶行列式=平行四边形有向面积；三阶=平行六面体有向体积。
  能"拖动"或"动画演示"行列式为零时图形退化，价值最高。
- 矩阵作为线性变换：单位正方形/圆在 2×2 矩阵作用下的形变（旋转、缩放、剪切、
  投影），直观解释为什么奇异矩阵对应面积为零、不可逆。
- 向量组的线性相关性：二维/三维中两个向量共线与不共线、三个向量共面与不共面。
- 初等行变换的几何效果：交换两行/倍加在图形上是什么操作。
- 克莱姆法则：用面积/体积比解释 D_j/D。
- 秩的几何意义：秩=像空间的维数。

【明确不要】
- 需要 Astro/Svelte/React 运行时的插件（除非我们已决定迁移，见另行评估）。
- 需要联网调用的在线服务（Desmos API、GeoGebra 在线版等）——可以离线用其导出功能。
- 只做静态排版、没有几何含义的"装饰性动画"。
- 依赖我们现有的 KaTeX 之外的公式渲染引擎。

【交付物】
1. 选定方案 + 选型理由 + 被淘汰方案及原因（至少比较 3 个候选）。
  候选方向供参考（不限于此）：Manim、Manim 的 SVG 导出、Asymptote、TikZ+dvisvgm、
  GeoGebra 导出、matplotlib animation、SVG+SMIL 手写、其他。
2. 一个**最小可用样例**：针对"二阶行列式的面积意义"生成一个图形，
   给出生成脚本、输出文件、文件体积、生成耗时。
3. 说明能否做**动画**（若只能静态图也接受，但要明确说清）。
4. 与 KaTeX/中文混排的兼容性说明。
5. 版本与可复现性说明。
```

## 第二部分：是否引入 Astro（评估与建议）

### 2.1 结论先行

**建议暂不引入 Astro，先做数学可视化。** 理由：Astro 解决的不是我们当前的问题，而它会带来一次高风险重构；数学可视化可以用现有构建流程直接接（内联 SVG）。

但如果你打算**把站点长期做大**（更多课程、卡片式首页、图片优化、组件复用），Astro 是一笔合理投资。下面把账算清。

### 2.2 Astro 能带来什么

| 收益 | 对我们的实际价值 |
| :--- | :--- |
| Shirone 插件生态可直接用 | **中等**。但已核查：`pretext-masonry` 是**瀑布流布局性能优化**（避免 offsetHeight 强制重排），不是动画/渲染插件；我们的站点是长文阅读，没有卡片瀑布流，用不上。`dynamic-svg`（内联 SVG 使其跟随主题）**有价值**，但它的思路我可以直接在现有构建里实现。 |
| 内容集合（Content Collections） | 中等。可以给 Markdown 加强类型 frontmatter 校验 |
| 组件化（.astro 组件） | 中等。我们的导航/面包屑/翻页目前是 build.mjs 里的模板字符串 |
| 图片优化 | 低。站点明确不含图片 |
| remark/rehype 生态 | 中高。数学可视化若走 rehype 插件路线，Astro 更顺 |

### 2.3 Astro 的代价（必须如实计入）

| 代价 | 说明 |
| :--- | :--- |
| **现有 747 行构建逻辑要迁移** | 其中一半是**我们特有的**，Astro 没有等价物，必须重写并逐条重新验证：<br>• `wrapBareCJK()`：把数学模式里的裸中文包进 `\text{}`（KaTeX 必需的兜底）<br>• `NAV_STRUCTURE` / `TEXTBOOK_ORDER`：手工维护的导航树与章节顺序<br>• 链接重写（`.md` → `.html`、`../` 层级、百分号编码兼容两种写法）<br>• `rootRel`/`data-depth` 计算与 **Pagefind 子路径前缀处理**（刚踩过两个坑）<br>• 非 md 资源降级为纯文本、模板链接降级 |
| **白名单负担加重** | 仓库要求逐文件精确白名单。Astro 会引入 `astro.config.mjs`、`src/`、可能的 `public/` 等。`node_modules` 已被忽略，但源码要逐个加白名单 |
| **`TARGET_FILES` 钩子校验要重做** | 现有钩子校验"构建清单与资料一致"（防止新增资料静默不上线）。Astro 用文件系统路由后，这条校验的形态会变，要重新设计 |
| **构建时间与依赖** | 现在 `npm install` 只要装 pagefind（2 个包、约 4 秒）。Astro 会拉几百个包，Actions 构建时间从 20 秒级升到分钟级 |
| **迁移期站点不可用风险** | 迁移期间新旧两套并存，容易出现"部分页面新、部分旧" |

### 2.4 推荐的路线

**路线 A（推荐，先做这件事）：不引入 Astro，直接在现有构建里接数学图形**

- 图形以**静态 SVG** 入库（或构建时生成）
- 在 `build.mjs` 里加一步：把 `.svg` 内联进 HTML（照 `dynamic-svg` 的思路），
  这样 SVG 内的 `var(--md-sys-color-primary)` 能跟随深浅主题
- 工作量：约 50 行构建代码 + CSS

**路线 B（若确定长期投入）：迁移到 Astro**

- 分阶段：先让 Astro 产出与现状**逐字节可比**的页面（保留同样的 HTML 结构），
  确认无回归后再启用 Astro 特性（组件、集合、插件）
- 迁移前必须先备份现有 `dist` 作为对照基线
- 迁移期间 `TARGET_FILES` 校验与白名单需同步改造

**无论哪条路线，数学可视化的需求书（第一部分）都可以先交给调研者**——它不依赖构建框架的选择，输出静态 SVG 的方案在两条路线上都能用。

### 2.5 待你决定

1. 走路线 A（不引入 Astro）还是路线 B（迁移 Astro）？
2. 数学图形接受**静态图**，还是必须有**动画**？（影响选型：Manim 系走 MP4/GIF，TikZ/Asymptote 走 SVG 静态图）
3. 若接受 MP4/GIF 动画，能否接受它**不随深浅主题变色**？
