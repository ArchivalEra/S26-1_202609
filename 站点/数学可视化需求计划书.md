# 数学可视化需求计划书

**目的**：给《工程数学基础》的解析配上数学图形与动画，让专科学生看懂"公式在说什么"。本文件分两部分：**第一部分是交给工具调研者的需求书**（可直接复制转交），**第二部分是对是否引入 Astro 的评估与建议**。

站点现有实现见[前端实现计划书](./前端实现计划书.md)；仓库规则见[维护条例](../维护条例.md)。

---

## 第一部分：交给调研者的需求书（可直接复制）

### 1.1 已定方向（不要再讨论这一点）

- **路线 A**：不引入 Astro，在现有 Node 构建（`站点/build.mjs`）里内联 SVG。
- **要动画，但必须是矢量动画**，具体形式按优先级：
  1. **SVG + CSS/SMIL 动画**（最优先）：纯线条与文字的运动，体积小（KB 级）、
     可随主题变色、无运行时依赖。
  2. **SVG 静态图 + 站点已有的 CSS 交互**（次优先）：鼠标悬停/点击时用 CSS 变换
     产生"动画感"，同样零运行时。
  3. **SVG 帧序列**（备选）：多张 SVG 帧 + 少量 CSS 轮播。
- **明确排除 MP4/GIF**：体积是矢量方案的数百倍，会逼我们依赖外部 CDN，
  访问速度不可接受。除非某效果只有位图能做，否则不采用。
- **pretext 与动画无关**（已核实）：`@shirone-plugins/pretext-masonry` 是瀑布流
  布局的性能优化，用纯算术预测卡片高度以避免 `offsetHeight` 强制重排，
  **不渲染任何图形**。不要把它列入候选方案。

### 1.2 需求书正文（复制以下内容转交）

```text
【任务】为《工程数学基础》课程解析站点，选定「数学矢量动画的自动生成方案」，
交付可复现的生成流程，并对「二阶行列式的面积意义」产出一个最小可用动画样例。

【背景】
- 站点由纯 Node 脚本（站点/build.mjs）把 Markdown 教材解析渲染为静态 HTML。
- 公式用 KaTeX 自持渲染；站点已内联 12 处 SVG 图标，主题用 [data-theme] 切换，
  CSS 变量如 var(--md-sys-color-primary) 在浅色/深色下自动改变。
- 部署在子路径 /repo/S26-1_202609/ 下，必须离线可用、零第三方请求。
- 目标读者是专科学生，需要的是"公式在几何上发生了什么"的直观演示。

【方向（已由需求方确定，不要推翻）】
- 输出 SVG 矢量动画，优先用 SVG + CSS animation 或 SMIL（<animate>/<animateTransform>）。
- 纯线条、纯字符、简单填充这类图形语言；不要拟真渲染、不要位图纹理。
- 体积目标：单个动画 < 100KB，整站新增 < 2MB。
- 颜色必须能用 CSS 变量（或至少留出可替换的颜色位），以跟随站点深浅主题。

【硬约束】
1. 构建期生成：生成脚本入库，产物为 .svg 文件；不允许运行时访问任何 CDN。
2. 不引入需要浏览器端 JS 运行时渲染的库（MathBox、D3、JSXGraph、p5.js 运行时等）。
   若工具本身是"生成器"（离线跑、吐 SVG 文件），则可以用，即使它用 Python/JS 写。
3. 中文与数学符号共存：动画里可能要标中文（如"第 i 行"）与数学符号。
4. 可复现：给出精确依赖版本与生成命令，能在干净环境重跑。
5. 说明动画的播放控制：能否循环、能否悬停播放、能否减少动效
   （prefers-reduced-motion）。站点会遵守该系统偏好。

【优先覆盖内容（按已解析章节排序，价值从高到低）】
1. 二阶行列式 = 平行四边形有向面积；动画演示当两向量共线时面积趋零
   （对应行列式为 0）。★首要样例请做这个
2. 三阶行列式 = 平行六面体有向体积（可用等轴测投影画三维示意）。
3. 矩阵作为线性变换：单位正方形/圆在 2×2 矩阵作用下形变（旋转、缩放、剪切、投影），
   直观说明奇异矩阵对应面积为零、不可逆。
4. 向量组线性相关性：二维两向量共线/不共线、三维三向量共面/不共面。
5. 初等行变换的几何效果（交换两行、倍加）。
6. 克莱姆法则用面积比/体积比解释 D_j/D。
7. 秩 = 像空间的维数。

【明确不要】
- MP4 / GIF / APNG 等位图动画（体积不可接受）。
- 需要联网的在线服务（Desmos API、GeoGebra 在线版）；其离线导出功能可以用。
- 装饰性动画（与数学含义无关的动效）。
- 替换 KaTeX 的公式渲染引擎。

【交付物】
1. 选型比较：至少 3 个候选方案，含选型理由与被淘汰原因。
   候选方向参考（不限于此）：手写 SVG + SMIL、SVG + CSS keyframes、
   SVGator 类工具导出、Manim 的 SVG 输出、matplotlib 动画导出 SVG 帧、
   Asymptote/TikZ 生成 SVG 后加动画、其他。
2. **最小可用样例**：二阶行列式面积意义的 SVG 动画，含
   生成脚本、输出文件、文件体积、生成耗时、以及"如何改颜色/改文案"的说明。
3. 明确回答：方案能否产出循环动画、能否悬停触发、是否有 prefers-reduced-motion 支持。
4. 与 KaTeX/中文混排的兼容性说明（字体、baseline 对齐）。
5. 版本与可复现性说明。
```

### 1.3 我这边（站点）会提供的接口

调研者只要交付 `.svg` 文件与生成脚本，我这边负责：

- 在 `站点/build.mjs` 增加一步：把 Markdown 里形如 `![说明](./math/xxx.svg)`（或约定标记）
  的**本地 SVG 内联进 HTML**，使它继承主题变量并可用 CSS 控制动画。
- 为动画提供统一的外层容器与主题色映射（把站点变量映射到 SVG 内的颜色）。
- 遵守 `prefers-reduced-motion`。
- 因此**调研者不需要懂本站点的构建**，只需产出标准 SVG。

## 第二部分：路线决策与实施接口

### 2.1 已定：路线 A（不引入 Astro）

**决策**：不引入 Astro，在现有 Node 构建里实现。

理由：
1. 我们当前的问题不是"缺框架"，而是"缺数学图形生成工具"——那是**独立的构建步骤**，与用不用 Astro 无关。
2. Astro 的收益对本项目不产生价值：需要迁移的 747 行构建逻辑中，近一半是**我们特有**的
   （`wrapBareCJK()` 数学模式裸中文兜底、手工维护的导航树 `NAV_STRUCTURE`、
   链接重写的两种编码兼容、`rootRel`/`data-depth` 与搜索索引的子路径前缀处理），
   这些 Astro 没有等价物，必须重写并重新验证。
3. 已核实：Shirone-Plugins 的 7 个插件里**没有数学动画能力**，所以"能用插件生态"
   这个引入理由不成立（详见附录）。

### 2.2 站点侧的实施接口（调研者交付 SVG 后，我做的部分）

**构建期内联**（在 `站点/build.mjs` 增加一步）：

- 识别 Markdown 中指向本地 `.svg` 的引用（如 `![二阶行列式面积](./math/det2-area.svg)`）
- 把 SVG 文件内容**内联**进 HTML 而非用 `<img>` 引用——只有内联才能继承
  `[data-theme]` 下的 CSS 变量、也只有内联才能让 CSS 动画作用于内部元素
- 给内联 SVG 套统一容器（`.math-figure`），并注入站点主题变量映射

**主题适配**：SVG 内用 `fill="var(--md-sys-color-primary)"` 这类变量即可自动变色。
调研者若不写变量，我用后处理把 `__PRIMARY__` 之类的占位符替换成站点变量。

**动效控制**：站点遵守 `prefers-reduced-motion: reduce`——该偏好下动画停在首帧
（CSS 里已有同类处理，复用即可）。

**体积与性能**：SVG 是文本，内联后可压缩；预计每个动画 5–50KB（对比同效果 MP4 约几 MB）。

### 2.3 若日后确实需要重新评估 Astro

届时按"分阶段迁移"推进：先让 Astro 产出与现状**逐字节可比**的页面，
确认无回归后再启用其特性；迁移前先备份 `dist` 作为对照基线；
`TARGET_FILES` 钩子校验与白名单需同步改造。

## 附：已核查的 Shirone-Plugins 插件清单

七个插件全部读过 README 与源码结构，**其中没有数学动画能力**，故"引入 Astro 就能用它的插件做动画"这一设想不成立。

| 插件 | 实际作用 | 对本站是否可用 |
| :--- | :--- | :--- |
| `pretext-masonry` | **瀑布流布局的性能优化**：用 `@chenglou/pretext` 的纯算术文本测量替代 `card.offsetHeight`，避免强制同步重排（微卡顿）。它做的是"预测卡片高度"，**不渲染任何图形**。 | 否。本站是长文阅读，无卡片瀑布流；也不是动画方案。 |
| `dynamic-svg` | 构建期内联本地 SVG，使其继承 M3 主题变量（`var(--primary)`），从而跟随深浅模式变色 | **思路已被采纳**：本站将自行在 `build.mjs` 实现内联（见 2.2） |
| `repo-pages` | 仓库页面相关 | 待确认，与数学可视化无关 |
| `strip-first-h1` | 去掉正文首个 H1 | 不需要 |
| `mixed-feed` | 混合内容流 | 否，个人站点专用 |
| `mangomesa-hub` | 站点聚合 | 否 |
| `what-im-doing` | Linux 桌面活动状态展示（Protobuf/SSE） | 否 |

**关于 pretext 的澄清**：它确实是一个很有意思的库（Unicode 分段 + 离屏 Canvas 测量 + 纯算术布局），但它的价值在**文本排版性能**，与"数学动画"是两个领域。若日后要做卡片式首页的性能优化，可以回头看它；做数学动画不要把它列入候选。
